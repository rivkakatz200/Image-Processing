## uint8 overflow table

| Expression | Guess | Result | Notes |
|---|---|---|---|
| print(x + 10) | [110 210 5] | [110 210 4] | Mistake: 250+10=260, 260 mod 256 = 4, not 5. |
| print(x + 100) | [200 45 95] | [200 44 94] | Mistake: 200+100=300, 300 mod 256 = 44 (not 45); 250+100=350, 350 mod 256 = 94 (not 95). Off by one error in mental mod arithmetic. |
| print(x - 150) | [205 50 100] | [206 50 100] | Mistake: 100-150 = -50, -50 mod 256 = 206, not 205. |
| print(x * 2) | [200 145 245] | [200 144 244] | Mistake: 200*2=400, 400 mod 256 = 144 (not 145); 250*2=500, 500 mod 256 = 244 (not 245). Off by one. |
| print(x.astype(np.int16) + 100) | [200 300 350] | [200 300 350] | Correct. Converting to int16 first avoids overflow, so results are exact. |
| print(x * 1.5) | [150 45 70] | [150. 300. 375.] | Mistake: multiplying by a float promotes the array to float64. No overflow occurs — 200*1.5=300, 250*1.5=375. The guess wrongly assumed it would stay uint8 and overflow. |
| print((x * 1.5).dtype) | uint8 | float64 | Mistake: NumPy upcasts to float64 when multiplying an integer array by a Python float. The result is no longer uint8. |
