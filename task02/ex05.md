# Exercise 5 – Answers

## Part 3 – Why does `method="np"` produce dark patches where the image was bright?

NumPy performs **modular (wrapping) arithmetic** on `uint8` arrays.  
`uint8` can only hold values 0–255. When the result of an addition exceeds 255,
NumPy wraps it around modulo 256 instead of clamping it to 255.

Example:

| Original pixel | + 100 (NumPy) | Expected (saturated) |
|---------------|---------------|----------------------|
| 200           | 300 % 256 = **44** | 255 |
| 180           | 280 % 256 = **24** | 255 |
| 100           | 200 | 200 |

Pixels that were **bright** (≥ 156) overflow and wrap back to a **small value**,
which matplotlib renders as **dark**. That is why bright regions appear unexpectedly
dark when using plain NumPy addition.

## Part 4 – What happens with `b=-100` in each method?

| Method | Behaviour for b = -100 |
|--------|------------------------|
| **`"np"` (img + b)** | For a `uint8` array, subtracting 100 from a pixel with value, say, 50 gives −50, which wraps to 206. Very dark pixels become **incorrectly bright**. |
| **`cv2.subtract`** | Performs **saturating subtraction**: any result below 0 is clamped to 0. Dark areas stay dark; bright areas are dimmed correctly. This is why `cv2.subtract` (not `cv2.add` with a negative value) should be used for darkening. Note: passing a negative value to `cv2.add` as `np.uint8(-100)` would wrap to 156, making things worse. |
| **`"clip"` (add_safe)** | Converts to `int16` first (so the subtraction is exact), then clamps with `np.clip`, and converts back to `uint8`. Result is correct: pixels don't go below 0. |

**When to use `cv2.subtract`:** whenever you need to decrease pixel values and want the
result to saturate at 0 rather than wrap around. It is the OpenCV counterpart of
`cv2.add` for subtraction.

## Part 5 – What changes when `vmin`/`vmax` are removed?

Without `vmin=0, vmax=255`, matplotlib **auto-scales** each image independently:
it maps the minimum pixel value in that image to black and the maximum to white.

Effects:

- The **`"np"` result** looked dim (because many pixels wrapped to low values) but
  with auto-scaling it is stretched to use the full 0–255 display range, hiding
  the overflow artefacts and making it look similar to the other methods.
- The **`"cv2"` and `"clip"` results** also get stretched, so they may look
  slightly brighter or have slightly higher contrast than the version with fixed
  `vmin/vmax`.
- The **original image** is stretched as well, so comparing it visually to the
  brightened versions becomes misleading.

**Why this matters:** `vmin=0, vmax=255` ensures every image uses the same display
scale, which is essential for honest visual comparison. Without it, matplotlib
compensates for the different value ranges and hides the actual differences between
methods.
