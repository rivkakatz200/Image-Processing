## Part 2 – What does `cv2.imread` return for an invalid filename?

`cv2.imread` returns `None` when the file does not exist or cannot be opened.
It does **not** raise an exception; it silently returns `None`.

The check added in the code is:

```python
if img is None:
    print(f"Error: could not read image '{filename}'.")
    sys.exit(1)
```

## Part 3 – Difference between the two `imshow` calls

OpenCV reads images and stores the colour channels in **BGR** order (Blue, Green, Red).  
Matplotlib's `imshow`, however, expects channels in **RGB** order (Red, Green, Blue).

- **Without conversion** – matplotlib interprets the Blue channel as Red and vice-versa, so the image looks like its red and blue areas are swapped (a flower that is red appears blue, sky that is blue appears red, etc.).
- **After `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`** – the channel order is corrected to RGB and the colours look as expected.

## Part 4 – Bright regions in each channel and why

Using the image `melanie-kreutz-flower.jpg` (a flower with a green background):

| Channel | Bright area | Reason |
|---------|-------------|--------|
| **Blue** | Sky / background highlights | Those areas have a high Blue component |
| **Green** | Leaves and stems | Vegetation reflects a lot of green light |
| **Red** | Petals of red/pink flowers | Flower petals reflect red light strongly |

A pixel appears **bright** in a channel when it contains a high intensity value (close to 255) for that colour.  
A pixel appears **dark** when its value for that colour is low (close to 0).

## Part 5 – Shape after reading with `IMREAD_GRAYSCALE`

When an image is read with `cv2.IMREAD_GRAYSCALE` the result is a **2-D array** — there is no third "channels" dimension because a single intensity value already describes each pixel.

Example for a 300 × 400 image:

- Colour (BGR): `(300, 400, 3)`
- Grayscale: `(300, 400)`
