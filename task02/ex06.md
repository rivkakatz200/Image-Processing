# Exercise 6 – Answers

## Part 1 – dtype and maximum value of `img * 1.5`

When a `uint8` array is multiplied by a **float** literal, NumPy automatically
**upcasts** the result to `float64`.  
This is because `uint8` cannot represent fractional values or values above 255,
so NumPy promotes the type to preserve the result accurately.

- **dtype:** `float64`
- **maximum value:** up to `255 * 1.5 = 382.5` (well above the uint8 range of 0–255)

## Part 3 – Difference between `img * 1.5` and `img * 2`

| Expression | Result dtype | Overflow behaviour |
|------------|--------------|--------------------|
| `img * 1.5` | `float64` | No overflow — values up to 382.5 are stored exactly |
| `img * 2`  | `uint8`   | **Wraps around** modulo 256: e.g. 200×2 = 400 → 400 % 256 = **144** |

When you write `img * 2`, the literal `2` is a Python **int**, and NumPy keeps the
original `uint8` dtype. Bright pixels (value > 127) overflow and wrap back to small
values, producing dark artefacts — exactly like the `"np"` method in exercise 5.

When you write `img * 1.5`, the literal `1.5` is a **float**, which forces NumPy to
upcast to `float64`, so all intermediate values are stored without loss.

## Part 4 – What happens with `k=0.5`?

Every pixel value is halved. The image becomes **darker overall** because the
distance from 0 is reduced for every pixel. Bright areas (e.g. value 200) become
medium-grey (100), and medium-grey areas become dark.

The dtype is still `float64` after multiplication (same reason as Part 1), so
clipping and casting back to `uint8` works cleanly without wrapping.

## Part 5 (bonus) – Stretching contrast around the mean

The formula `(img - m) * k + m` scales pixel values around the image mean `m`:

- Pixels **above** the mean: their distance from `m` is multiplied by `k`, so
  they move **further away** (brighter when k > 1, closer when k < 1).
- Pixels **below** the mean: same logic — they move further down (darker when
  k > 1).
- The **mean pixel itself** stays unchanged (distance from `m` is 0).

This keeps the overall brightness constant while increasing (k > 1) or
decreasing (k < 1) the contrast.

**dtype of `img - m`:** `float64`, because `m = img.mean()` returns a Python/NumPy
float and NumPy upcasts the subtraction result to `float64`.

**Risk of overflow:** There is **no** uint8 overflow at the subtraction step
because the subtraction is done in `float64`. However, the final result of
`(img - m) * k + m` **can** exceed 255 or go below 0 for large `k` values, so
`np.clip(result, 0, 255)` is still necessary before casting back to `uint8`.
